Use the Base API to retrieve the API's name and version, validate messages with the echo route, and check service health. None of these routes require authentication.

## Base URL

```text Base URL
https://api.alexxweb.com
```

The version 1 path is `/api/v1`. Append the endpoint path to the base URL.

<Info>
  The earlier documentation used `/v1`. The current API implements `/api/v1`; serving it at `/v1` requires a gateway rewrite.
</Info>

## Authentication

<Check>
  The current Base API routes do not require an API key or bearer token.
</Check>

## Endpoints

| Method | Path | Description |
| --- | --- | --- |
| `GET` | [`/api/v1`](#get-api-information) | Returns the API name and version |
| `POST` | [`/api/v1/echo`](#echo-a-message) | Validates a message and returns it unchanged |
| `GET` | [`/health`](#health-check) | Returns `{"status":"ok"}` when the API responds |
| `GET` | [`/openapi.json`](#openapi-specification) | Returns the OpenAPI 3.1 specification |

## Get API information

```http
GET /api/v1
```

No request body or query parameters are required.

<CodeGroup>

```bash cURL
curl https://api.alexxweb.com/api/v1
```

```powershell PowerShell
Invoke-RestMethod https://api.alexxweb.com/api/v1
```

</CodeGroup>

### Response

A successful request returns `200 OK`:

```json 200 OK
{
  "name": "base-api",
  "version": "1.0.0"
}
```

<ResponseField name="name" type="string" required>
  The API identifier. Currently `base-api`.
</ResponseField>

<ResponseField name="version" type="string" required>
  The API version. Currently `1.0.0`.
</ResponseField>

## Echo a message

```http
POST /api/v1/echo
```

Send a JSON object containing only a `message` string. The API validates it and returns it unchanged.

### Request body

<ParamField body="message" type="string" required>
  The message to echo. Must contain 1 to 1000 JavaScript UTF-16 code units. Whitespace is preserved.
</ParamField>

<CodeGroup>

```bash cURL
curl https://api.alexxweb.com/api/v1/echo \
  -H "Content-Type: application/json" \
  -d '{"message":"hello"}'
```

```powershell PowerShell
Invoke-RestMethod https://api.alexxweb.com/api/v1/echo `
  -Method Post `
  -ContentType "application/json" `
  -Body '{"message":"hello"}'
```

</CodeGroup>

### Response

```json 200 OK
{
  "message": "hello"
}
```

### Limits and validation

- `message` must be 1 to 1000 UTF-16 code units. Some characters, including many emoji, count as two.
- Extra properties are rejected.
- The total request body must not exceed 16,384 bytes.
- The request must use `Content-Type: application/json`.

<Note>
  Messages are not stored.
</Note>

## Health check

```http
GET /health
```

Returns the following when the API responds:

```json 200 OK
{
  "status": "ok"
}
```

## OpenAPI specification

```http
GET /openapi.json
```

## Errors

API responses use `application/json; charset=utf-8`. Every API response includes an `X-Request-Id` header, and error responses include the same ID in the body:

```json Error response
{
  "error": {
    "message": "Route not found",
    "requestId": "123e4567-e89b-42d3-a456-426614174000"
  }
}
```

| Status | Cause |
| --- | --- |
| `400` | Invalid JSON or invalid message on the echo route |
| `404` | Unknown path or unsupported HTTP method |
| `413` | Echo request body exceeds 16 KiB |
| `415` | Echo request is missing `Content-Type: application/json` or uses another content type |
| `500` | Unexpected API error |

<Warning>
  Paths match exactly. For example, `/api/v1` is supported and `/api/v1/` returns `404`.
</Warning>

<Note>
  A `502 Bad Gateway` response comes from the gateway when it cannot reach the API. It may not use the API's JSON error format or include an API request ID.
</Note>
