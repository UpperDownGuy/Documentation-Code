An API key lets your app read or change AlexWeb data. Each key has permissions called **scopes**.

[Create a developer account](/v1/developer-accounts), sign in to the [developer console](https://api.alexxweb.com/developers), and create a key for your app. Existing API users can also connect to the console with a key. Never put a key in a public website or a URL.

## Try it

Replace `YOUR_API_KEY` with your key to check that it works.

<CodeGroup>

```powershell CURL
curl https://api.alexxweb.com/api/v1/auth/me -H "Authorization: Bearer YOUR_API_KEY"
```

</CodeGroup>

## What you'll see

```json
{
  "account": { "id": "ACCOUNT_ID", "username": "your_username", "name": "Your account" },
  "credential": {
    "id": "KEY_ID",
    "kind": "api_key",
    "scopes": ["resources:read", "events:read"]
  },
  "api": { "name": "AlexWeb API", "version": "1.2.0" }
}
```

- **scopes** lists what this key can do.
- **id** identifies the key without showing its secret value.

You can also send an API key with `X-API-Key: YOUR_API_KEY`.

## Create a key

Your current key needs `keys:manage`. The new key can only receive permissions your current key already has.

<CodeGroup>

```powershell CURL
curl https://api.alexxweb.com/api/v1/keys -H "Authorization: Bearer YOUR_API_KEY" -H "Content-Type: application/json" -d '{"name":"My app","scopes":["resources:read","events:read"],"expiresInDays":90}'
```

</CodeGroup>

Save the response's **key** privately. It is shown once. `expiresInDays` is optional and defaults to 90 days; it accepts 1–365. A key created by another API key cannot outlive that creating key. Keys created from your developer account's console session can use the selected lifetime; they are not limited to the browser session's 12 hours.

## Other requests

| Request | What it does | Required scope |
| --- | --- | --- |
| `GET /api/v1/auth/me` | Checks your key or OAuth token. | Any valid credential |
| `GET /api/v1/keys` | Lists key names, permissions and expiry dates. | `keys:manage` |
| `POST /api/v1/keys` | Creates a key. | `keys:manage` |
| `POST /api/v1/keys/{id}/rotate` | Replaces a key with the same permissions and remaining expiry. | `keys:manage` |
| `DELETE /api/v1/keys/{id}` | Revokes a key immediately. | `keys:manage` |

## Rotate or revoke a key

**Rotate** replaces a key when an app needs a fresh credential. In the developer console, choose the key and use its rotation action. The API revokes the previous key and returns a new key in one operation. Save the new **key** value immediately; it is shown once.

```bash
curl -X POST https://api.alexxweb.com/api/v1/keys/KEY_ID/rotate \
  -H "Authorization: Bearer YOUR_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

The replacement keeps the original key's permissions. It preserves the remaining expiry or shortens it to the management credential's expiry when that expires sooner. Rotation does not extend the key's lifetime or grant additional permissions. Your management credential must also be allowed to grant all the original key's scopes.

Update the app using that key with the new value. For [Home Assistant](/v1/home-assistant#replace-credentials-or-reconnect), follow the credential replacement steps after rotation. Work authorized by the old key, including its OAuth grants, webhooks, or schedules, loses that authorization when the old key is revoked; reconnect or recreate those connections with a current credential as needed.

**Revoke** ends a key's access without creating a replacement. Use it when an app should no longer connect. The list shows metadata such as the key's identifier, name, scopes, and expiry; it cannot recover the full secret of an existing key.

## Permissions

| Scope | Allows |
| --- | --- |
| `resources:read` / `resources:write` | Read / change resources. |
| `events:read` / `events:write` | Read events, including full resource changes / publish custom events. |
| `integrations:read` | Read Home Assistant integration information. |
| `webhooks:manage` | Manage event webhooks. |
| `schedules:manage` | Manage schedules. |
| `usage:read` | Read usage and audit history. |
| `keys:manage` / `apps:manage` | Manage keys / registered applications. |

Missing or invalid keys return **401**. Missing permissions return **403**.
